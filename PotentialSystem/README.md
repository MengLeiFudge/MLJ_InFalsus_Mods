# PotentialSystem · 潜力值系统

为 In Falsus 添加基于 Arcaea 新版规则的潜力值（PTT）。当前版本 1.0.0，适用于 Windows IL2CPP 版游戏和 BepInEx 6。

## 功能

- 选歌界面顶部正中央显示放大的账号 PTT 和 Arcaea 潜力值徽章，下方显示当前曲库的动态理论上限。
- 左右歌曲卡片和中央选中歌曲下方显示当前难度的 `#排名 单曲潜力值`，例如 `#12 11.111`。排名按全部已游玩谱面的最佳表现计算，超过 B50 的成绩也有排名；未游玩的谱面不显示虚假排名。
- 点击顶部 PTT 打开全部最佳成绩页面，以封面卡片显示排名、歌名、难度、定数、打击分数、通关状态和单曲潜力值。支持滚动与歌名、作者、难度搜索，列表包含全部已游玩谱面，每个歌曲难度保留一项最佳表现。
- 成绩页提供“导出 B50 到剪贴板”按钮，按成绩和游戏封面独立生成 2400 像素宽的分享图片，包含账号 PTT、动态上限及 B50/B10 均值，可直接粘贴到聊天或图片应用。
- 原版排序旁新增“潜力值排序”入口，依次切换降序、升序和原版顺序。按当前选择难度的单曲潜力值排序，未游玩的歌曲始终排在已游玩歌曲之后；点击原版排序按钮可直接返回原版模式。
- 结算界面以更大的文字和徽章显示账号 PTT，在约 1.2 秒内从旧值过渡到新值，并显示本次单曲潜力值、增加值或 Keep。
- 直接读取游戏当前加载的 SongData 与各可用谱面的 Rating，以原生整数等级作为定数。歌曲和等级不保存在模组的固定表中；游戏增加歌曲后，新谱面会自动纳入。
- 每次载入账号从完整逐局 history 计算最佳 PTT，并在历史变化时同步。独立文件保存对应真实纪录的已知 UTC 时间，关闭模组期间的成绩也可从历史补入。
- 模组成绩按原版存档目录隔离，不改变原版 .sav 格式。

选歌入口和排名使用原版字体、布局及按钮输入；成绩浏览页使用适应窗口尺寸的中文字体与封面网格。页面打开时持有独立输入，关闭或按 Escape 后归还选歌输入。排序模式只在当前选歌场景生效，不写入原版排序枚举。

导出图片根据完整成绩快照取前 50 项，独立绘图，不受游戏分辨率、当前选歌或成绩页滚动位置影响。已有成绩不足 50 项时按实际数量展示。封面加载或剪贴板被占用时明确提示导出失败；关闭页面取消尚未完成的导出。剪贴板只在玩家点击导出按钮且图片生成完成后更新。

## 计算方式

每首歌的不同难度作为不同谱面。游戏 PlayerScore 除以 10 后对应 Arcaea 的分数尺度；谱面整数等级为 C，归一化分数为 A，本次成绩完成等级达到 DiveCleared（含 FullLink、PerfectDive）时 bonus=0.2，否则为 0。原生 Lamp 仅按 Pace 判断，可能与未判定音符导致的 DiveFailed 不一致，因此 PTT 的通关状态统一由完成等级决定：

```text
A >= 10,000,000：C + 2 + bonus
9,800,000 <= A < 10,000,000：C + 1 + (A - 9,800,000) / 200,000 + bonus
A < 9,800,000：max(0, C + (A - 9,500,000) / 300,000 + bonus)
```

保存每谱面分数增量最大的原始成绩，再以当前游戏等级计算单曲潜力值。取最高的 50 项作为 B50，B10 为其中最高的 10 项：

```text
PTT = (B50 单曲潜力值总和 + B10 单曲潜力值总和) / 60
```

分母始终为 60，成绩不足时缺项贡献零。当前等级不变时，每个谱面的最高值只升不降，因此账号 PTT 只升不降。原版若调整已有谱面等级、改变可用状态或谱面身份，模组会按新的官方数据重新计算。

显示截断到三位小数，内部计算保留 decimal 精度。增加值按显示前后的差计算；显示未变化时为 Keep。

理论上限使用游戏当前所有可用谱面的 C+2.2 套用同一 B50/B10 公式计算。当前调查的曲库理论上限为 14.950，这个数值随游戏曲库动态计算。

徽章使用以下固定门槛；达到每档下界时切换。选歌、结算、完整成绩浏览和 B50 导出共用同一规则。

| 本游戏潜力值范围 | 徽章外观 | 对应 Arcaea 原门槛 |
| --- | --- | --- |
| 0.000～3.999 | 青色，无星 | 0.000 |
| 4.000～7.999 | 绿色，无星 | 3.500 |
| 8.000～10.999 | 浅紫色，无星 | 7.000 |
| 11.000～11.999 | 紫色，外围光效，无星 | 10.000 |
| 12.000～12.999 | 红色，外围光效，无星 | 11.000 |
| 13.000～13.499 | 粉红色，一星 | 12.000 |
| 13.500～13.999 | 粉红色，二星 | 12.500 |
| 14.000 及以上 | 玫红色，圆形图案，三星 | 13.000 |

## 安装

需要 BepInEx-BepInExPack_IL2CPP-6.0.755。将 PotentialSystem.dll 放入当前启动方式使用的 BepInEx/plugins/MengLei-PotentialSystem 目录，重启游戏后进入选歌界面。

从本仓库编译时，DLL 位于 PotentialSystem/bin/Release/PotentialSystem.dll。安装该 DLL 即可运行，不依赖本仓库其他三个模组。

## 成绩文件与异常

独立记录保存在 `savestate_V3.sav` 相同目录的 `savestate_ptt_v1.json`，不写入原生存档。正常替换时，上一版保留为 `savestate_ptt_v1.json.bak`；文件归属于原版账号/存档目录，切换 BepInEx profile 不会混用其他 Steam 账号的成绩。

每次载入账号均遍历 history 的实际 length，逐局使用同一次成绩的分数与完成等级，按歌曲／难度计算最高表现。较低分的通关成绩仍可能比更高分的未通关成绩有更高 PTT。当前有效谱面的数值从历史重建；独立文件只为歌曲、难度、谱面身份、分数和完成等级一致的真实成绩提供已知时间，暂时移除的谱面继续归档。

同步同时检查原生成绩对象、更新号和 history 实际条数。游戏未破最高分或完成等级纪录时，updateId 不增加，但逐局历史仍然追加，因此须以条数识别变化。结算先捕获本局 UTC 时间和更新前数值，再同步历史，保持增加动画。

根字段为 `schemaVersion: 1`、`rule: "integer-rating-v1"`、UTC `importedAt` 和 `bestPlays`。每条记录包含 `songId`、`difficulty`（1/2/4/8）、`chartId`、`score`（十进制字符串）、`lamp`（用于 PTT 的通关状态）、`resultClear`、`constant`、未截断 `potential`、`achievedAt` 和 `source`。`history` 来源为原生真实历史，`play` 为模组捕获的真实结算及时间；原生时间为零或无效时 `achievedAt` 为 null。`importedAt` 仅表示首次创建文件的时间。

新结算由模组捕获 UTC 时间，表现更高时更新记录；相同表现优先已知的较早时间，历史同步不会用 null 覆盖已知时间。关闭模组期间的游玩也会补入，无法还原的完成时间保持 null。游戏调整定数时，文件中的定数与 PTT 同步重算，保留成绩和取得时间。网页的第三个 Best 50 Tab 可直接读取此文件并显示来源与时间。

旧 `PotentialSystem/integer-v1.json` 不再读取或生成。新文件成功写入后，旧文件及其 `.bak` 会移为同目录的 `savestate_ptt_v1.json.legacy.<唯一标识>.bak`，移除旧路径并保留可恢复数据。旧格式不作为可靠最佳成绩导入。已有 v1 文件中的 `source: "summary"` 条目由加载器识别后丢弃，当前谱面随完整历史重建；保存前一版仍由 `.bak` 保留。新文档只输出真实 `history`／`play` 纪录。

读取失败或发现不支持的格式时，模组保留原文件并显示 Data error，不把坏档当作空档覆盖。请查看 BepInEx 日志，备份并修复文件后重启游戏。备份文件由用户判断后恢复，模组不自动用较旧备份替换当前成绩。

写入或旧格式归档失败时，待处理状态保留在内存，并显示 Unsaved。新的场景刷新或结算事件会再尝试保存；成绩可在下次载入时从 history 恢复，但尚未成功保存的模组 UTC 时间无法由原生存档补回。

首次安装或在已经打开的结算界面加载插件时，已有原生成绩作为初始基线，不把它们伪装成本次新增 PTT；之后的结算显示正常增加动画。当前原版历史列表的 1024 是初始容量，写满会扩容，模组读取实际 length。历史缺失或结构无效时停止该账号的计算并报告错误；有效的空历史可生成零成绩文件。
